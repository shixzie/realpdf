# AGENTS.md

Fully client-side PDF editor (no server, no uploads). React + fabric.js + pdf.js + pdf-lib, built by Vite, deployed as a Cloudflare Worker serving static assets.

## Commands

```bash
npm install
npm run dev        # Vite dev server, http://localhost:5173
npm run typecheck  # tsc --noEmit
npm test           # vitest run: unit + all e2e suites (boots its own Vite server)
npm test -- tests/e2e/text-edit.test.mjs   # one suite (fast path)
APP_URL=http://localhost:4173/ npm test    # run against an already-running server
npm run build      # typecheck + vite build -> dist/ ; then npm run preview (:4173)
npm run sample     # writes ./sample.pdf, required by the scripts below
npm run visual     # visual fidelity check; needs `npm run dev` + ./sample.pdf
npm run cf:dev     # build + wrangler dev (Cloudflare runtime)
npm run types      # regenerate worker-configuration.d.ts after wrangler config changes
npm run deploy     # build + wrangler deploy -> PRODUCTION (realpdf.app); only when asked
```

- There is no lint or format script. Match existing style manually: no semicolons, single quotes, 2-space indent, trailing commas.
- Verification order that matters: `npm run typecheck && npm test`; `npm run build` re-runs typecheck.
- Other scripts in `scripts/` (screenshots, demo) are not npm-wired; they need a running server on :5173 and `./sample.pdf` (`screenshot-forms.mjs` expects `cf:dev` on :8787).

## Testing

- Vitest suites are `.mjs` files under `tests/`, not co-located with source. Unit tests run without a browser; e2e suites drive real headless Chromium via Playwright and verify exported PDFs by re-rendering them.
- `vitest.config.ts` sets `fileParallelism: false` deliberately: suites share one app, one fixture set and one output directory. Don't change it to speed things up.
- `tests/global-setup.mjs` generates fixtures into `$OUT_DIR` (default `/tmp/realpdf-tests`) and starts its own Vite server unless `APP_URL` is set.
- Reuse `tests/helpers/app.mjs` (`openPdf`, `dragOnPage`, `savePdf`, `pixelStats`, `pdfText`, ...) instead of writing new page setup.
- Assertions use soft `check()` on purpose so one failure doesn't abort the flow.
- Playwright ships its own browser cache; if Chromium is missing run `npx playwright install chromium`.
- Only English UI strings are asserted; other locales may be worded freely (see `docs/localization.md`).

## Architecture

- Entry: `index.html` -> `src/main.tsx` -> `App.tsx`. One zustand store (`src/store.ts`) holds pages, tools, forms and snapshot-based undo/redo.
- Annotations are fabric.js canvases, one per visible page, registered in `src/lib/canvasRegistry.ts`; stored per page via `src/lib/serialize.ts` (image assets stay out of undo snapshots). Canvas coordinates are PDF points.
- Every export/tool path must use the baked document: `exportController.ts` / `currentDocument.ts` (`bakedCurrentBytes()` applies form values, annotations and page order) -> `export.ts` (pdf-lib). Raw `state.bytes` is the untouched original.
- Existing-text editing rewrites page content streams (`src/lib/contentEdit.ts`) and re-renders a scratch page with pdf.js so the on-screen preview matches the file. The real file uses the same rewrite.
- pdf.js runtime assets (wasm decoders, standard fonts, CMaps, ICC) are served from our own origin, never a CDN: dev middleware plus `closeBundle()` copy in `vite.config.ts` maps `node_modules/pdfjs-dist/{wasm,standard_fonts,cmaps,iccs}` to `/pdfjs-assets/`.
- i18n is dependency-free: user-facing strings go through `t()` from `src/i18n/`; adding a locale is one dictionary file plus a registry entry, and `npm run typecheck` enforces key parity.
- `README.md` "Limitations" documents deliberate fallbacks (non-reflowing text replacement, Office fidelity, Standard-14-only new text). Those are trade-offs, not bugs; read before "fixing" them.

## Repo gotchas

- tsconfig is strict with `verbatimModuleSyntax`, `noUnusedLocals`/`noUnusedParameters`: type-only imports need `import type` or the build fails.
- `worker-configuration.d.ts` is generated by `npm run types`; never edit it by hand.
- `worker/index.ts` re-implements `public/_headers` (security headers, asset cache lifetimes) because `run_worker_first` bypasses the assets layer. Change caching/headers in both places together.
- `window.__realpdf` (store/canvas handles) is exposed only in dev builds (`src/main.tsx`) for `scripts/visual-check.mjs`; e2e tests use the UI only, so they also pass against a production build.
- `dist/` and `sample.pdf` are gitignored; `dist/pdfjs-assets/` exists only after a build.
- `docs/localization.md` and `docs/selection-options.md` cover behavior that isn't obvious from the code; `docs/localization.md` references a removed `scripts/e2e-ui.mjs` — ignore that line.
